# 서울대 경영대학 소식 자동 요약 시스템 설계

## 배경 / 목적

다음 세 군데에서 올라오는 새 소식을 사람이 직접 찾아다니지 않고, 정해진 시간에 자동으로 모아서 카카오톡으로 받아보고 싶다.

1. 경영대학 학과 홈페이지 공지사항 (`https://cba.snu.ac.kr/newsroom/notice?sc=y`)
2. 서울대 학번 메일로 오는 공지 (현재 Gmail로 자동 포워딩 설정되어 있음)
3. 서울대 비교과 프로그램 (`https://extra.snu.ac.kr`)

## 실행 환경

- **GitHub Actions**(무료 클라우드 스케줄러)에서 실행. 사용자의 컴퓨터가 켜져 있을 필요 없음.
- 실행 주기: 매주 **월요일 + 목요일 아침 8시(KST)**. cron 표현식은 UTC 기준으로 환산해서 워크플로에 등록 (KST 08:00 = UTC 전날 23:00).
- GitHub Actions의 "Run workflow" 수동 트리거도 함께 열어둬서 언제든 즉시 테스트 가능하게 함.

## 전체 데이터 흐름

```
[스케줄 트리거: 월/목 08:00 KST]
        ↓
  1) cba.snu.ac.kr 공지 목록 수집 (requests + BeautifulSoup)
  2) Gmail에서 "from:*.snu.ac.kr" 신규 메일 수집 (IMAP)
  3) extra.snu.ac.kr 프로그램 목록 수집 (Playwright headless)
        ↓
  각 소스별로 "마지막 확인 지점(state)" 이후의 신규 항목만 필터링
        ↓
  구글 Gemini 무료 API로 항목별 한 줄 요약 생성
        ↓
  신규 항목을 소스별로 그룹핑 + 정렬
        ↓
  카카오톡 "나에게 보내기" API로 발송
        ↓
  state 파일 업데이트 후 커밋
```

## 소스별 수집 방식

### 1. 학과 홈페이지 (cba.snu.ac.kr)
- 로그인 불필요, 정적 HTML 테이블 게시판.
- `requests`로 목록 페이지를 가져와 `BeautifulSoup`으로 파싱.
- 항목: 제목, 분류(일반/모집/장학/시설), 게시일, 게시글 링크(상세 URL), 게시글 번호.
- 게시글 번호(또는 날짜)를 기준으로 마지막 확인 지점보다 새 것만 추출.

### 2. Gmail 공지 메일
- 인증 방식: **Gmail 앱 비밀번호 + IMAP** (OAuth보다 개인 자동화에 설정이 간단해서 채택).
- 검색 조건: `from:*.snu.ac.kr` (또는 발신 도메인이 `@snu.ac.kr`인 메일), 마지막 확인 시각 이후 수신분.
- 항목: 제목, 발신자, 수신 시각, 메일 원문 링크(Gmail 웹 링크 또는 메일 ID).
- 광고성/개인 메일과 섞이지 않도록 발신 도메인 필터만 적용 (별도 라벨 분류는 최초 버전에서는 하지 않음 — 필요하면 추후 카테고리 세분화 가능).

### 3. 비교과 프로그램 (extra.snu.ac.kr)
- 로그인 불필요하지만, 접속 시 NetFunnel 대기 화면 → JS 리다이렉트를 거쳐야 실제 콘텐츠가 로딩됨.
- **Playwright(headless Chromium)**로 접속 → 대기 화면 통과 대기 → 프로그램 목록 렌더링 완료까지 대기 → 목록 파싱.
- 항목: 프로그램명, 모집기간/일정, 상세 링크, (가능하면) 프로그램 ID.
- 사이트 구조가 자바스크립트 SPA라 목록 selector가 바뀌면 파싱이 깨질 수 있음 → 실패 시 에러 처리 섹션대로 처리.

## 중복 방지 (State 관리)

- 저장소 내 `state.json` 파일에 소스별 "마지막으로 확인한 지점"을 기록:
  ```json
  {
    "cba_notice": { "last_seen_id": 12345 },
    "gmail": { "last_seen_at": "2026-07-16T22:00:00Z" },
    "extra_snu": { "last_seen_id": "P-2026-0033" }
  }
  ```
- 매 실행 시작 시 이 파일을 읽어 신규 항목만 필터링하고, 발송 성공 후 최신 값으로 갱신하여 같은 워크플로 실행 안에서 git commit.
- 커밋은 자동화 봇 명의로 수행(예: `github-actions[bot]`), 사용자가 신경 쓸 필요 없음.

## 메시지 포맷 (Gemini 무료 API로 한 줄 요약)

- 신규 항목마다 **구글 Gemini API(무료 할당량)** 를 호출해서 제목/본문을 한 줄로 압축 요약.
- 주 2회, 매번 최대 수십 건 수준의 호출이라 Gemini 무료 할당량(분당/일일 요청 수 제한) 안에서 충분히 처리 가능 — 사실상 0원.
- 소스별로 그룹핑, 각 항목은 `한 줄 요약 (마감/일정 정보)` + 원문 링크.
- 신규 항목이 하나도 없는 소스는 그 그룹 자체를 생략.
- 세 소스 모두 신규 항목이 없으면 "이번엔 새 소식 없음"이라는 한 줄만 발송 (확인은 정상적으로 되었다는 것을 알리기 위함, 무발송 아님).
- **무료 할당량을 초과해 Gemini 호출이 실패하는 경우**: 해당 항목은 AI 요약 대신 원래 제목을 그대로 사용해서 발송 (요약 없이도 소식 자체는 반드시 전달됨).

예시:
```
📌 7/20(월) 학교 소식 요약 (신규 5건)

[학과 공지] 2건
• 세계지식포럼 참가자 모집, 국내외 석학 강연 참여 기회 (~8/7)
  https://cba.snu.ac.kr/...
• 2학기 명예교수실 TA 모집, 성적 우수자 우대 (~7/27)
  https://cba.snu.ac.kr/...

[이메일 공지] 2건
• 경력개발센터 AI진로캠프, 5일간 포트폴리오 제작 실습 (~8/2)
  https://mail.google.com/...

[비교과 프로그램] 1건
• (한 줄 요약)
  https://extra.snu.ac.kr/...
```

## 카카오톡 발송

- 카카오 디벨로퍼스에 개인 앱 등록 → 카카오 로그인 활성화 → "나에게 보내기(me/message)" API 사용.
- 최초 1회 사용자 본인이 브라우저에서 로그인/동의하여 **refresh token**을 발급받고, 이를 GitHub Secrets에 저장.
- 매 실행 시 refresh token으로 access token을 갱신한 뒤 메시지 발송 (access token은 단명하므로 매번 갱신 필요).

## 에러 처리

- 세 소스는 서로 독립적으로 수집: 한 소스가 실패해도 나머지는 정상 진행.
- 실패한 소스는 카카오톡 메시지 안에 `⚠️ ○○ 확인 실패` 한 줄로 표시.
- 상세 에러 로그는 GitHub Actions 실행 로그에 남김 (터미널 stdout/stderr).
- 카카오톡 발송 자체가 실패하는 경우(토큰 만료/API 오류 등)에는 사용자에게 알릴 방법이 없으므로, GitHub Actions의 기본 기능인 "워크플로 실패 시 이메일 알림"에 의존 (별도 설정 불필요, GitHub 계정 이메일로 자동 발송됨).

## 초기 설정 (사용자가 직접 해야 하는 일)

1. GitHub 계정 준비 (없으면 무료로 신규 생성) 및 이 저장소를 GitHub에 올리기
2. Google 계정 2단계 인증 활성화 + Gmail 앱 비밀번호 발급
3. 카카오 디벨로퍼스 개인 앱 생성 + 카카오 로그인 동의 + refresh token 최초 발급
4. Google AI Studio에서 Gemini API 키 무료 발급 (구글 계정만 있으면 됨)
5. 아래 값들을 GitHub 저장소 Settings → Secrets 에 등록:
   - `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`
   - `KAKAO_REST_API_KEY`, `KAKAO_REFRESH_TOKEN`
   - `GEMINI_API_KEY`
6. 이후에는 완전 자동, 별도 조작 불필요.

## 테스트 계획

1. 소스별 수집 스크립트를 각각 단독 실행해서 파싱 결과 확인 (학과 공지 → Gmail → 비교과 순).
2. 전체 파이프라인을 GitHub Actions "수동 실행"으로 1회 돌려 실제 카카오톡 수신 확인.
3. state 파일을 최신으로 만들어둔 뒤 재실행하여 "신규 소식 없음" 메시지가 정상적으로 오는지 확인.
4. 일부러 존재하지 않는 값으로 한 소스를 실패시켜(예: 잘못된 URL) 나머지 소스는 정상 발송되고 실패 표시가 뜨는지 확인.

## 범위 제외 (이번 버전에서 하지 않는 것)

- 이메일 카테고리 세분화(라벨링) — 발신 도메인 필터만 적용
- 비교과 신청 마감 임박 알림 등 부가 알림 기능
- 유료 AI API(Claude/OpenAI 등)로의 전환 — Gemini 무료 할당량으로 충분하다고 판단, 초과 시에도 유료 전환 없이 제목 그대로 발송(에러 처리 섹션 참고)
