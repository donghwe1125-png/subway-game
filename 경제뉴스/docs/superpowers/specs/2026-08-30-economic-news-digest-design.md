# 세계 경제뉴스 텔레그램 다이제스트 — 설계 문서

- 작성일: 2026-08-30
- 상태: 설계 확정, 구현 대기
- 참고 프로젝트: `소식 자동화` (같은 저장소, SNU 공지사항 다이제스트 — 유사한 파이프라인을 이미 검증한 선례)

## 1. 목표

세계 경제 뉴스를 한 번도 안 읽어본 사람도 이해할 수 있도록, 매일 아침 "오늘의 세계 경제뉴스 3가지"를 쉬운 구어체로 풀어서 텔레그램으로 보내준다. 각 뉴스는 배경 설명을 포함해 조금 길게(3개 합쳐서 읽는 데 약 3분) 써서, 왜 중요한지까지 이해할 수 있게 한다.

## 2. 사용자가 확정한 요구사항

| 항목 | 결정 |
|---|---|
| 전송 채널 | 텔레그램 (기존 `소식 자동화` 프로젝트의 봇/채팅을 재사용) |
| 뉴스 소스 | 해외 유명 경제 언론사 RSS (국내 언론의 국제 섹션 아님) |
| 소스→선별 방식 | RSS로 헤드라인 후보를 먼저 모으고, AI가 그중에서 고름 (AI 자체 웹검색 방식 아님 — 출처 신뢰성/안정성 우선) |
| 전송 시각 | 매일 07:00~08:00 KST |
| 뉴스 개수 | 3개 (개수를 늘리지 않고, 각 뉴스의 설명을 길게) |
| 분량/톤 | 뉴스당 "무슨 일이 있었는지" + "왜 중요한지"를 배경 설명 포함해 상세히, 친근한 구어체, 3개 합쳐 약 3분 분량 |
| 상태 저장(중복 방지) | 불필요 — 매일 새로 3개를 고르는 방식이라 이전 발송 이력을 기억할 필요 없음 (`소식 자동화`와의 차이점) |

## 3. 전체 흐름

```
[1. 뉴스 수집]        여러 언론사 RSS에서 오늘자 헤드라인 후보 목록을 모은다
        │
[2. AI 선별 + 설명]   Gemini에게 후보 목록을 주고, 가장 중요한 3개를 고르게 한 뒤
        │             각각 "무슨 일" + "왜 중요한지"를 쉬운 구어체로 쓰게 한다 (JSON으로 응답)
        │
[3. 메시지 포맷]      JSON 3개 항목을 텔레그램 메시지 문자열로 조립한다
        │
[4. 전송]             텔레그램 봇 API로 발송한다
        │
[5. 자동 실행]        GitHub Actions가 매일 07:00 KST에 위 과정을 실행한다
```

## 4. 구성 요소

`경제뉴스/` 프로젝트 폴더 아래, `소식 자동화`의 검증된 패턴을 재사용해 구성한다.

- `scripts/news_sources.py` — RSS 소스별 fetch 함수. 소스: BBC Business, CNBC, MarketWatch, Yahoo Finance (구현 시점에 실제로 살아있는 피드인지 확인 후 필요하면 교체). 각 함수는 `{title, summary, url, source, published}` 리스트를 반환하고, 실패 시 예외를 던진다.
- `scripts/curator.py` — Gemini 호출 모듈. 모든 소스의 후보 헤드라인을 하나의 프롬프트에 담아, 가장 중요한 3개를 선정하고 각각을 아래 JSON 스키마로 작성하게 한다.
  ```json
  {
    "title_kr": "짧은 한글 제목",
    "what_happened": "무슨 일이 있었는지 (배경 설명 포함, 상세히)",
    "why_it_matters": "왜 중요한지 (한국/개인 생활에 미치는 영향 포함, 상세히)",
    "source_name": "Reuters",
    "url": "https://..."
  }
  ```
  JSON 파싱 실패 시 1회 재시도하고, 그래도 실패하면 해당 항목은 제외한다.
- `scripts/message_formatter.py` — JSON 3개 항목을 예시 형식(이모지, 구분선, 출처 링크 포함)의 텔레그램 메시지로 조립. 너무 길어지면 여러 통으로 분할(`소식 자동화`의 `MAX_CHARS` 분할 로직 재사용).
- `scripts/telegram_sender.py` — `소식 자동화/scripts/telegram_sender.py`를 그대로 재사용.
- `scripts/main.py` — 오케스트레이터: 수집 → 선별/설명 → 포맷 → 전송을 순서대로 실행.
- `.github/workflows/economic-news-digest.yml` — `cron: '0 22 * * *'` (UTC 22:00 = KST 07:00 다음날), `workflow_dispatch` 수동 실행도 허용.

## 5. 에러 처리

- 일부 RSS 소스가 실패해도 나머지 소스만으로 진행한다 (전체가 멈추지 않음).
- 후보가 부족해 3개를 못 채우면 채워진 만큼만 보낸다.
- 모든 소스가 실패하거나 Gemini 호출이 최종 실패하면, "오늘은 뉴스를 가져오지 못했어요" 알림을 텔레그램으로 보내 침묵 상태를 방지한다.

## 6. 필요한 사전 준비물

- 텔레그램 봇 토큰 / 채팅 ID: `소식 자동화`에서 쓰는 값 재사용 (신규 발급 불필요).
- Gemini API 키: `소식 자동화`에서 쓰는 값 재사용.
- GitHub Secrets: 이미 저장소에 등록되어 있다면 추가 작업 불필요. 새 워크플로우 파일에서도 동일한 시크릿 이름을 참조한다.

## 7. 알려진 리스크 / 한계

- **RSS 피드 안정성**: 언론사가 피드 주소나 구조를 바꾸면 수집이 깨질 수 있다. `소식 자동화`에서도 같은 이유로 스크래퍼를 여러 번 손본 이력이 있다 — 완전히 "한 번 만들면 끝"은 아니다.
- **GitHub Actions 스케줄 오차**: cron은 정확히 07:00에 실행된다고 보장하지 않는다 (보통 몇 분~15분 정도 지연 가능).
- **AI 선별 품질**: Gemini가 고르는 3개가 항상 객관적으로 "가장 중요한" 뉴스라는 보장은 없다. 초기 운영 후 프롬프트를 조정하며 개선한다.
- **무료 API 한도**: Gemini 무료 등급 호출 한도(분당 요청 수) 안에서 하루 1회 호출이라 문제 없을 것으로 예상되지만, 응답 실패 시 위 에러 처리 로직으로 대응한다.

## 8. 테스트 계획

`소식 자동화`와 동일하게 pytest 기반, 외부 호출(RSS, Gemini, 텔레그램)은 모두 mock 처리:
- `news_sources.py`: 각 소스 파서가 샘플 RSS를 올바르게 파싱하는지, 실패 시 예외를 던지는지
- `curator.py`: 정상 JSON 응답 파싱, 잘못된 JSON 응답 시 재시도/제외 처리
- `message_formatter.py`: 3개 항목 포맷 결과, 길이 초과 시 분할 결과
- `main.py`: 일부 소스 실패, 전체 실패, 정상 케이스에 대한 통합 흐름 테스트
